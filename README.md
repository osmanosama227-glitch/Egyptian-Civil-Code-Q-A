# Egyptian Civil Code Q&A

Question answering over the **Egyptian Civil Code (Law 131 of 1948)** in formal Arabic. Questions can be in formal Arabic or Egyptian colloquial, typed or placed inside a Word/PDF file.

The system works in two stages:

1. **Retrieve:** bge-m3 (dense) + BM25 (keyword), merged with reciprocal rank fusion, find the most likely article in the whole code.
2. **Generate:** Llama 3.1 8B, fine-tuned with QLoRA, answers using only that article.

```text
Civil Code (.docx) → parse → articles JSON
articles JSON → Qwen2.5-7B-Instruct → synthetic QA pairs
QA pairs → clean, filter, split by article → QLoRA fine-tune Llama 3.1 8B → adapter
Question → bge-m3 + BM25 retrieval → top article → Llama + LoRA → answer
```

> **Status: research prototype, work in progress.** Final full-run numbers, human evaluation and a hand-written gold test set are not done yet (see [METHODOLOGY.md](METHODOLOGY.md), sections 2 and 11). This is not legal advice.

## Repository contents

| Path | What it does |
| --- | --- |
| `notebooks/Egyptian_Law_0_Generate_QA_no_API.ipynb` | Generates 3 QA pairs per article with Qwen2.5-7B-Instruct (4-bit), no paid API |
| `notebooks/Egyptian_Law_2_Train_and_Evaluate_Llama.ipynb` | Cleans data, splits by article, QLoRA fine-tunes Llama 3.1 8B, evaluates on held-out articles |

| `app.py` | Streamlit test app: ask a question, see the article used, rate the answer |

## How to run

Every notebook runs in its own Colab session (GPU: T4 or better). Files move between them by download and upload:

| Step | Upload | Produces |
| --- | --- | --- |
| Notebook 0 | `egyptian_civil_code_articles.json` | `egyptian_civil_qa.json` |
| Notebook 2 | `egyptian_civil_qa.json` | `egyptian_lora_model.zip`, evaluation CSV |
| Notebook 3 | `egyptian_civil_code_articles2.json` + `egyptian_lora_model.zip` | `rag_pipeline_results.csv`, confidence intervals |
| Notebook 4 / `app.py` | `app.py` + articles JSON + adapter zip | `validation_log.csv` (human ratings) |

To run the app locally with a CUDA GPU:

```bash
pip install -r requirements.txt
streamlit run app.py --server.fileWatcherType none
```

`app.py` expects `egyptian_civil_code_articles2.json` and `egyptian_lora_model.zip` next to it.

## Data and model files are not in this repo

- **Articles JSON and QA JSON:** derived from the Civil Code text and generated by Qwen2.5-7B-Instruct. Add them under `data/` only after checking the source and licence terms.
- **LoRA adapter (`egyptian_lora_model.zip`):** the adapter fits only the 4-bit Llama 3.1 8B base (`unsloth/Meta-Llama-3.1-8B-bnb-4bit`). Check the Llama 3.1 licence before sharing it. Link the hosted adapter here: _TODO_.

## Models

| Model | Role |
| --- | --- |
| `Qwen/Qwen2.5-7B-Instruct` | Writes synthetic QA pairs |
| `unsloth/Meta-Llama-3.1-8B-bnb-4bit` + LoRA | Answers questions |
| `BAAI/bge-m3` | Dense retrieval |
| BM25 (`rank_bm25`) | Keyword retrieval |
| `paraphrase-multilingual-MiniLM-L12-v2` | Semantic-similarity metric only |

## Limitations

Training and test pairs are synthetic; reference answers can be wrong; only the civil code is covered; retrieval errors dominate end-to-end results, so oracle scores overstate real performance. Details in [METHODOLOGY.md](METHODOLOGY.md), section 12.
